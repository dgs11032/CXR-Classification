## 3. 3클래스 라벨 생성

원본 폴더는 `NORMAL/PNEUMONIA`의 2분류 구조이므로 폐렴 파일명의 문자열을 이용해 다음과 같이 3개 클래스를 생성했다.

```text
NORMAL 폴더                         → NORMAL
PNEUMONIA/*bacteria*.jpeg          → BACTERIAL_PNEUMONIA
PNEUMONIA/*virus*.jpeg             → VIRAL_PNEUMONIA
```

파일명 정보는 정답 라벨 생성에만 사용하며 모델 입력에는 포함하지 않는다. 알려지지 않은 파일명 형식은 임의로 분류하지 않고 오류로 처리한다.

## 5. 파일명 기반 그룹 식별자

파일명의 숫자 ID는 전역 환자 ID로 바로 사용할 수 없었다.

- 동일한 `person<ID>`가 bacterial과 viral 파일명에서 대량으로 재사용된다.
- `NORMAL2-IM-*` 번호와 `IM-*` 번호도 겹친다.
- raw ID만 사용하면 원본 train/test 사이에 264개의 거짓 중복이 발생한다.

따라서 누수 제어용 `group_id`는 클래스와 `NORMAL2` 네임스페이스를 포함해 구성했다. 이 값은 공식 환자 ID가 아닌 **파일명 기반 그룹 식별자**다. 실제 병원 환자 메타데이터가 제공되지 않았으므로 진정한 환자 단위 독립성을 보장할 수 없다는 점을 최종 보고서에 한계로 명시한다.

## 6. 정확한 중복 처리

전체 원본 목록인 `inventory.csv`와 공식 test 624장은 그대로 보존한다.

다만 학습과 validation에서 동일한 픽셀이 여러 번 가중되는 것을 막기 위해 원본 train에서 SHA-256이 동일한 중복 26장을 제거했다. 따라서 모델링 development는 5,190장이다.

최종 평가 시 다음 두 결과를 모두 산출할 수 있도록 test manifest를 두 종류로 저장했다.

- `test.csv`: 공식 test 624장
- `test_deduplicated.csv`: 정확한 중복을 제거한 618장

dHash가 같은 이미지는 실제 동일 이미지라고 단정할 수 없으므로 삭제하지 않고 검토 후보로만 기록했다.

## 7. 최종 데이터 분할

중복을 제거한 development 5,190장을 `StratifiedGroupKFold(seed=42)` 후보 중 클래스 분포와 15% 목표 비율이 가장 가까운 fold로 나눴다.

| 구분 | 전체 | 정상 | 세균성 폐렴 | 바이러스성 폐렴 |
|---|---:|---:|---:|---:|
| Train | 4,448 | 1,148 | 2,153 | 1,147 |
| Validation | 742 | 192 | 359 | 191 |
| 공식 Test(잠금) | 624 | 234 | 242 | 148 |
| 중복 제거 Test(잠금) | 618 | 231 | 240 | 147 |

검증 결과:

- 실제 validation 비율: 14.30%
- Train/validation `group_id` 중복: 0
- Train/validation SHA-256 중복: 0
- Train과 validation 내부의 정확한 이미지 중복: 0
- Development/test namespaced `group_id` 중복: 0
- 기존 validation 16장은 학습과 모델 선택에서 제외

## 8. E0 기준 모델 설정

- Backbone: ImageNet 사전학습 ConvNeXt-Tiny
- 구조: 일반적인 3클래스 분류
- Encoder Feature 차원: 768
- 전체 파라미터: 27,822,435
- Loss: CrossEntropyLoss
- Optimizer: AdamW
- Scheduler: CosineAnnealingLR
- 모델 선택 지표: Validation Macro F1
- Train 입력: 이미지마다 독립적인 약한 증강 2-view
- Validation 입력: 무작위 증강이 없는 단일 view
- Test 평가: 수행하지 않음

E0에서도 두 view를 사용하는 이유는 이후 E1에서 동일한 이미지 노출량을 유지한 채 SupCon Loss의 추가 효과만 비교하기 위해서다.
