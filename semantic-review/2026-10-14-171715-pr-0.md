# ConvNeXt-Tiny E0 학습·검증 dry-run 기반 구축

> **후속 수정 완료(2026-10-14):** 아래 리뷰의 P1 두 건과 probability 범위·checkpoint 안전 로딩 문제를 수정했다. Full-fit은 `scheduler.step()` 후 checkpoint를 저장하며, Dry-run은 model·optimizer·scheduler state를 모두 복원해 동등성을 확인한다. `weights_only=True`와 확률 `[0,1]` 검증을 적용했고 재실행 18개 검사가 모두 통과했다. 아래 본문은 수정 전 발견 사항을 보존한 리뷰 기록이다.

STEP 7은 cache의 `IMAGENET1K_V1` ConvNeXt-Tiny에 `Linear(768, 3)` head를 붙이고, two-view 학습과 single-view validation을 E0 engine으로 연결한다. 1개 train batch와 클래스별 2장으로 forward 계약, CE 역전파, 지표, 입력 불변성, checkpoint 저장을 확인하며 전체 epoch·Test·AWS·E1–E3는 실행하지 않는다. 모델·데이터 경계는 요구에 맞지만, full fit의 best checkpoint는 완료 epoch보다 한 단계 이전 scheduler 상태를 저장하고 dry-run은 optimizer/scheduler를 복원하지 않은 채 “round-trip 통과”로 판정한다. Git 메타데이터가 없어 `main` 대비 추가·수정 라인을 분리할 수 없었으므로 지정된 최신 파일과 산출물을 리뷰 범위로 삼았다.

Watch for: **[P1, confirmed]** full-fit best checkpoint의 scheduler 상태가 epoch와 어긋나 재개 시 LR schedule이 한 epoch 밀리며, **[P1, confirmed]** dry-run의 checkpoint 성공 판정은 model logits만 비교해 optimizer/scheduler 복원을 증명하지 않는다. **[P2, confirmed]** unweighted CE는 bacterial class에 각 다른 클래스보다 약 1.9배 많은 학습 비중을 주고, **[P2, confirmed]** `weights_only=False` checkpoint loading은 신뢰되지 않은 파일에 임의 코드 실행 경계를 연다.

**Verdict**: NEEDS_CHANGES

## High-level view

모델은 ConvNeXt-Tiny의 feature extractor, pooling, final normalization을 보존하고 classifier만 3-class linear head로 교체한다. cache 존재를 먼저 확인하고 다운로드를 기본 거부하며, `forward_features`와 `forward`는 각각 `[B,768]` feature와 `[B,3]` logits 계약을 제공한다.

학습 engine은 sample-contiguous `[B,V,C,H,W]`를 `[B*V,C,H,W]`로 펴고 label을 같은 순서로 확장한다. CE mean은 고정된 두 view를 동일 가중 평균하고, validation은 single-view만 받아 softmax 이후 metric과 prediction artifact를 만든다.

best model 선택은 validation Macro F1과 early stopping으로 연결된다. **[P1, confirmed]** checkpoint 저장이 scheduler step보다 먼저라서 `epoch=N`과 해당 epoch 완료 후의 LR 상태가 일치하지 않는다.

checkpoint payload에는 전체 학습 상태가 있지만 dry-run reload에는 model만 전달된다. **[P1, confirmed]** `checkpoint_round_trip.passed=true`와 “저장 상태가 완전히 복원” 문구는 실제 검증 범위보다 넓다.

full/head-only gating은 최소 실행에서 각각 27,822,435개/2,307개 trainable parameter로 확인됐다. **[P2, confirmed]** persisted dry-run은 full mode만 다뤄 head-only optimizer step이 backbone을 보존하는지는 회귀 검증하지 않는다.

validation split은 train과 path/group/hash 중복이 없지만 학습 분포는 1,148 NORMAL, 2,153 bacterial, 1,147 viral이다. **[P2, likely]** unweighted CE가 bacterial gradient 기회를 약 1.9배 늘리므로 Macro F1 선택만으로 minority-class optimization bias를 제어하기 어렵다.

<summary>Issues (7)</summary>

1. **[P1, confirmed] Full-fit scheduler checkpoint 시점** — best checkpoint가 `scheduler.step()` 전에 저장되어 완료 epoch보다 LR schedule이 한 단계 뒤처진다. step과 저장 순서를 일관되게 바꾸고 재개 후 다음 LR을 검증해야 한다.
2. **[P1, confirmed] 불완전한 checkpoint round-trip 성공 판정** — dry-run은 model만 reload하면서 optimizer/scheduler까지 완전 복원됐다고 보고한다. 새 optimizer/scheduler를 전달해 state와 다음 step의 동등성을 검사해야 한다.
3. **[P2, confirmed] 안전하지 않은 checkpoint 역직렬화** — `weights_only=False`는 교체되거나 외부에서 온 checkpoint를 로드할 때 임의 코드 실행을 허용한다. 현재 payload로 동작하는 `weights_only=True`로 전환해야 한다.
4. **[P2, likely] 불균형한 CE 학습 비중** — bacterial 표본이 각 다른 클래스의 약 1.9배라 unweighted CE가 minority recall과 calibration을 불리하게 만들 수 있다. baseline 선택을 명시하고 per-class 결과를 보존하며 필요하면 weighted CE 또는 balanced sampler를 별도 비교해야 한다.
5. **[P2, confirmed] probability 범위 검증 누락** — 합만 1이면 음수나 1 초과 값도 metric API가 수용한다. 각 원소의 `[0,1]` 범위를 검증해야 한다.
6. **[P2, confirmed] head-only update 검증 누락** — scope별 parameter 수만 맞고 head-only step 후 backbone 불변성은 persisted artifact가 확인하지 않는다. synthetic 또는 한 batch parameter-delta test를 추가해야 한다.
7. **[P2, confirmed] rotation의 극단 border 값** — `fill=0` 회전 영역이 ImageNet normalize 후 극단값이 되며 framing shortcut을 만들 수 있다. full fit 전에 train 표본으로 시각 검증하고 문제가 보이면 승인된 border fill/padding으로 고정해야 한다.

## Best Macro F1 checkpoint의 한 epoch 늦은 scheduler

`fit_e0`는 개선된 Macro F1 checkpoint를 저장한 다음 `scheduler.step()`을 호출한다. **[P1, confirmed]** `epoch=1` checkpoint는 epoch 1의 model/AdamW moments와 아직 epoch 0인 LR schedule을 함께 담으므로, 이 지점에서 재개하면 다음 epoch도 초기 LR로 학습하고 cosine schedule이 한 epoch 밀린다.

Dry-run은 반대로 scheduler를 먼저 step해 artifact에 `last_epoch=1`, LR `9.8918306e-05`를 저장하므로 이 full-fit 비대칭을 검증하지 못한다. scheduler step을 checkpoint 저장 전에 수행하고 epoch를 completed epoch로 정의하거나, `next_epoch`와 step 시점을 payload에 명시한 뒤 resume의 다음 LR을 회귀 검증해야 한다.

## Model-only 비교로 축소된 checkpoint round-trip

Artifact에는 optimizer 182개 state entry와 scheduler state가 저장됐지만 reload 호출에는 model만 전달되고, 통과 조건도 epoch와 model logits 차이뿐이다. **[P1, confirmed]** `checkpoint_round_trip: passed`는 model weight만 증명하며 전체 학습 재개 상태를 증명하지 않는다.

별도 최소 실행에서 현재 loader가 새 optimizer/scheduler로 182개 state와 `last_epoch=1`을 복원하는 것은 확인됐다. Reload model용 optimizer/scheduler도 생성해 state dict equality와 동일 입력에서의 다음 optimizer/scheduler step 결과를 비교하면 과도한 성공 주장을 실제 계약으로 바꿀 수 있다.

## Checkpoint 파일의 신뢰 경계

`load_checkpoint`는 `torch.load(..., weights_only=False)`를 사용하며 신뢰 전제는 docstring에만 있다. **[P2, confirmed]** 향후 사용자 지정 resume 경로가 연결되거나 artifact가 교체되면 pickle 역직렬화 중 임의 코드가 실행될 수 있다. 현재 artifact는 `weights_only=True`로 model과 optimizer 182개 state까지 로드됨을 확인했으므로 안전 모드로 전환할 수 있다.

## 불균형 분포 위의 two-view 평균

두 view와 `[y0,y0,y1,y1,…]` mapping은 16 source/32 view artifact로 확인됐다. 학습 manifest는 1,148/2,153/1,147이고 sampler와 CE class weight가 없으므로 **[P2, likely]** bacterial class가 각 다른 class보다 약 1.9배 자주 gradient에 기여해 minority recall과 calibration을 희생할 수 있다.

Unweighted E0 baseline을 유지한다면 이 선택을 명시하고 per-class precision/recall과 confusion matrix를 full-fit 산출물로 보존해야 한다. 균형 최적화가 필요하면 class-weighted CE나 balanced sampler 중 하나를 별도 승인된 설정으로 비교해 이중 보정을 피해야 한다.

## 공용 metric이 받는 비확률 값

`classification_metrics`는 shape, finite, row sum, target range를 검사하지만 각 값의 `[0,1]` 범위는 검사하지 않는다. **[P2, confirmed]** `[1.2,-0.1,-0.1]`처럼 합이 1인 행도 실제 최소 실행에서 정상 처리되어 accuracy 1.0을 반환했다. 내부 `evaluate`는 softmax라 영향받지 않지만 공용 API가 잘못된 artifact를 조용히 수용하므로 lower/upper bound 검증이 필요하다.

## Head-only와 회전 설정의 full-fit 전 검증 공백

Persisted config와 dry-run은 full mode만 실행한다. **[P2, confirmed]** head-only trainable parameter 수는 2,307개로 맞지만 optimizer step 후 backbone state 불변성과 head 변화는 검증하지 않는다. Test나 full epoch 없이 synthetic tensor 또는 허용된 한 batch로 parameter delta를 비교할 수 있다.

Train rotation은 확률 0.5, ±5°, `fill=0`이며 normalize 후 fill 영역은 채널별 약 -2의 값이 된다. **[P2, confirmed]** report도 검은 삼각형 가능성을 기록하지만 full fit 전에 영향은 확인되지 않았다. STEP 7에서 설정을 임의 변경하지 않는 trade-off는 존중하되, Test가 아닌 class별 train 표본으로 시각 검증하고 문제가 보일 때만 border median fill 또는 reflect/edge padding을 승인받아 고정해야 한다.
