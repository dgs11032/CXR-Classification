# 파일명 그룹 기반 ConvNeXt-Tiny E0 베이스라인 구현 검토 기록

## 검토 결론

**판정: 조건부 통과**

데이터 준비, E0 모델 구조, 2-view 학습, validation 기반 체크포인트 선택, 평가 지표 및 산출물 생성은 정상적으로 구현되었다. ImageNet 사전학습 ConvNeXt-Tiny를 사용한 소규모 스모크 학습도 성공했다.

다만 현재 실행한 학습은 train 12장과 validation 12장을 사용한 파이프라인 검증용 실행이다. 전체 train 4,448장과 validation 742장을 이용한 E0 본 학습은 아직 실행하지 않았으므로, E0 실험이 최종 완료된 상태는 아니다.

## 1. 이번 구현에서 수행한 작업

### 1.1 3클래스 라벨 생성

데이터 폴더와 파일명을 이용해 다음 세 클래스를 생성한다.

- `NORMAL` 폴더: `NORMAL`
- `PNEUMONIA` 폴더에서 파일명에 `bacteria` 포함: `BACTERIAL_PNEUMONIA`
- `PNEUMONIA` 폴더에서 파일명에 `virus` 포함: `VIRAL_PNEUMONIA`

알 수 없는 폴더 또는 파일명 형식은 임의로 처리하지 않고 오류를 발생시키도록 구현했다. 파일명은 정답 라벨 생성에만 사용하며 모델 입력에는 포함하지 않는다.

### 1.2 전체 데이터 목록과 품질 정보 생성

전체 5,856장에 대해 다음 정보를 수집했다.

- 원본 split
- 3클래스 라벨
- 파일명 기반 환자 식별 토큰
- 이미지 너비와 높이
- 이미지 색상 모드
- 파일 크기
- SHA-256 해시
- dHash

PIL 무결성 검사를 통과하지 못하거나 라벨을 해석할 수 없는 이미지는 없었다.

### 1.3 파일명 그룹 식별자 구성

파일명에서 `person<ID>` 또는 `IM-<ID>`를 추출했다. 분석 결과 동일한 숫자 ID가 다음처럼 여러 네임스페이스에서 재사용되고 있었다.

- 세균성 폐렴과 바이러스성 폐렴에서 동일한 `person<ID>`가 반복됨
- `NORMAL2-IM-*`와 `IM-*`의 숫자가 반복됨

따라서 숫자 ID만 동일하다는 이유로 같은 환자로 병합하지 않고, 클래스 및 `NORMAL2` 네임스페이스를 포함한 `group_id`를 구성했다.

이 방식은 파일명 번호 충돌로 서로 다른 영상을 한 그룹으로 잘못 묶는 문제를 방지한다. 하지만 공식 환자 메타데이터가 없으므로 이것을 확정적인 실제 환자 ID라고 주장할 수는 없다. 최종 보고서에서는 **파일명 기반 그룹 분할**이라고 표현해야 한다.

### 1.4 정확한 중복 이미지 처리

최초 검토에서 동일한 SHA-256을 가진 이미지가 development와 test 내부에 존재한다는 사실이 확인되었다. 이후 다음과 같이 보정했다.

- 전체 원본 목록인 `inventory.csv`는 그대로 보존
- 원본 train 5,216장에서 동일한 픽셀의 중복 26장을 제거
- 모델링 development 5,190장을 train/validation으로 분할
- 공식 test 624장은 그대로 보존
- 정확한 중복을 제거한 test 618장을 `test_deduplicated.csv`로 추가 보존

정확히 같은 이미지가 서로 다른 라벨을 가진 경우는 없었고, 원본 train/val/test 사이를 가로지르는 정확한 SHA-256 중복도 없었다.

dHash가 같은 503개 행은 단순 검토 후보로만 기록했다. dHash가 같더라도 실제 동일 이미지라고 단정할 수 없으므로 자동 삭제하지 않았다.

### 1.5 Train/Validation 재분할

기존 validation은 16장뿐이고 바이러스성 폐렴이 없으므로 모델 선택에 사용하지 않았다.

중복 제거 후 development 5,190장을 파일명 기반 `group_id`를 사용해 계층화 그룹 분할했다.

| 구분 | 전체 | 정상 | 세균성 폐렴 | 바이러스성 폐렴 |
|---|---:|---:|---:|---:|
| Train | 4,448 | 1,148 | 2,153 | 1,147 |
| Validation | 742 | 192 | 359 | 191 |
| 공식 Test | 624 | 234 | 242 | 148 |
| 중복 제거 Test | 618 | 231 | 240 | 147 |

검증 결과:

- Train/validation `group_id` 중복: 0
- Train/validation SHA-256 중복: 0
- Development/test namespaced `group_id` 중복: 0
- Train과 validation 내부의 정확한 이미지 중복: 0

## 2. E0 모델 구현 검토

### 2.1 모델 구조

E0는 다음 구조의 일반적인 3클래스 분류 모델이다.

```text
흉부 X-ray
    ↓
ImageNet 사전학습 ConvNeXt-Tiny
    ↓
768차원 Encoder Feature
    ↓
Dropout + Linear Classification Head
    ↓
3개 Logit
```

실행 검증 결과:

- Encoder Feature: `(B, 768)`
- 분류 Logit: `(B, 3)`
- 전체 파라미터: 27,822,435개

ConvNeXt-Tiny의 마지막 분류기를 직접 사용하는 대신 Encoder Feature를 명시적으로 반환하도록 구성했다. 이 구조는 이후 E1에서 같은 Feature에 Projection Head를 연결하고 E2/E3에서 Detection/Subtype Head를 연결하기에 적합하다.

### 2.2 2-view 학습

각 원본 학습 이미지에서 서로 독립적인 약한 증강 View 두 개를 생성한다.

```text
원본 이미지
 ├── View 1 → CE Loss
 └── View 2 → CE Loss
```

두 View를 하나의 배치로 합쳐 Cross Entropy를 계산한다. 이후 E1과 E3에서 같은 두 View에 SupCon Loss만 추가하면 E0↔E1 및 E2↔E3 비교에서 이미지 노출량 차이를 줄일 수 있다.

향후 모든 실험에서 다음 조건을 동일하게 유지해야 한다.

- 원본 이미지 기준 Batch Size
- 데이터 증강 설정
- 각 이미지의 View 수
- Optimizer step 수
- Backbone 초기화
- Epoch 수 또는 Early Stopping 기준

### 2.3 학습과 체크포인트 선택

E0 학습 설정은 다음과 같다.

- Loss: CrossEntropyLoss
- Optimizer: AdamW
- Scheduler: CosineAnnealingLR
- 모델 선택 기준: Validation Macro F1
- Early Stopping 적용
- Gradient clipping 적용
- CUDA 사용 시 Automatic Mixed Precision 적용

각 Epoch에서 train loss와 validation loss, Accuracy, Macro F1, Macro AUROC를 기록한다. Validation Macro F1이 가장 높은 Epoch의 가중치를 CPU 상태로 저장하고, 학습 종료 후 해당 체크포인트를 다시 불러와 validation을 재평가한다.

### 2.4 평가 지표

다음 3클래스 지표를 계산한다.

- Accuracy
- Balanced Accuracy
- Macro F1
- One-vs-Rest Macro AUROC
- 클래스별 Precision
- 클래스별 Recall
- 클래스별 F1
- 클래스별 AUROC
- 3×3 Confusion Matrix

클래스가 하나라도 없는 소규모 평가 입력에서는 AUROC 계산이 불가능할 수 있으므로 예외를 처리하도록 구현했다.

## 3. Test 잠금 검토

학습 코드는 다음 두 파일만 읽는다.

- `train.csv`
- `validation.csv`

`test.csv`와 `test_deduplicated.csv`를 읽거나 평가하는 학습 경로는 구현하지 않았다. 따라서 현재 스모크 학습 및 체크포인트 선택 과정에서 공식 test 데이터가 사용되지 않았다.

최종 모델 구조와 Hyperparameter가 확정된 뒤에만 별도의 test 평가 경로를 추가해야 한다.

## 4. 스모크 학습 결과

ImageNet 사전학습 ConvNeXt-Tiny와 MPS 장치를 사용해 train 12장, validation 12장으로 5 Epoch를 실행했다.

- Best Epoch: 2
- Validation Accuracy: 0.7500
- Validation Macro F1: 0.7662
- Validation Macro AUROC: 0.7994
- NaN/Inf 발생: 없음
- 체크포인트 복원 및 재평가: 성공
- Test 평가: 수행하지 않음

이 결과는 모델의 실제 일반화 성능을 나타내지 않는다. 데이터 로딩, 2-view 생성, Forward, Loss, Backward, Optimizer, Scheduler, Validation, Checkpoint 및 산출물 저장이 처음부터 끝까지 동작하는지 확인하기 위한 실행 결과다.

## 5. 현재 해결된 문제

1. **macOS Python 인증서 문제**  
   ImageNet 가중치 다운로드 시 기본 CA 인증서 경로가 없어 TLS 오류가 발생했다. 인증서 검증을 끄지 않고 `certifi` CA bundle을 사용하도록 수정했다.

2. **PIL 이미지 검증 순서 문제**  
   이미지 해시 계산 후 `verify()`를 호출하면서 닫힌 파일 포인터를 참조하는 문제가 발생했다. 무결성 검증과 이미지 메타데이터 계산을 별도 `open`으로 분리했다.

3. **파일명 숫자 ID 충돌 문제**  
   동일한 숫자가 bacterial, viral, NORMAL2 네임스페이스에 재사용되는 것을 확인하고 namespaced `group_id`를 도입했다.

4. **정확한 중복 이미지 가중 문제**  
   모델링 development에서 정확한 SHA-256 중복 26장을 제거하고, 공식 test와 중복 제거 test를 별도로 보존했다.

## 6. 아직 남아 있는 사항

### 6.1 전체 E0 학습

현재는 12장 스모크 실행만 완료했다. 전체 train 4,448장과 validation 742장을 이용한 E0 학습을 실행하고 다음 결과를 보존해야 한다.

- 전체 학습 이력
- 최적 Epoch
- E0 최종 Validation Macro F1
- E0 Validation 클래스별 지표
- E0 Confusion Matrix
- 전체 E0 Checkpoint

### 6.2 실제 환자 ID 확인 한계

현재 `group_id`는 파일명 구조를 분석해 만든 누수 방지용 그룹이다. 공식 환자 메타데이터가 제공되지 않았으므로 실제 환자 단위 분할이라고 단정하면 안 된다.

가능하면 데이터셋 공식 문서에서 파일명 규칙을 확인하고, 그렇지 못하면 이 제한을 최종 보고서에 명시해야 한다.

### 6.3 반복 Seed

현재 데이터 분할과 스모크 학습은 Seed 42를 사용한다. E0~E3의 2×2 Factorial 결과를 안정적으로 비교하려면 핵심 실험에서 동일한 복수 Seed를 사용하는 것이 좋다.

### 6.4 자동 회귀 검사

현재 파일명 라벨, 분할, Test 잠금, 2-view 형태, 모델 출력 및 Metric을 보호하는 별도 자동 테스트 코드는 만들지 않았다. 지금은 실제 데이터 기반 스모크 실행과 명시적 invariant 검사로 검증했다.

## 7. 파일별 역할

- `src/p1_cxr/data.py`: 라벨 생성, 파일명 그룹 생성, 이미지 목록, 중복 검사, 분할, 전처리, DataLoader
- `src/p1_cxr/models.py`: ConvNeXt-Tiny Encoder와 E0 Flat Classification Head
- `src/p1_cxr/training.py`: 2-view CE 학습, validation 평가, 체크포인트 및 결과 저장
- `src/p1_cxr/metrics.py`: 3클래스 평가 지표와 이미지별 예측 결과 생성
- `src/p1_cxr/config.py`: JSON 설정 로딩과 경로 해석
- `configs/e0.json`: E0 데이터·모델·학습 설정
- `scripts/prepare_data.py`: 데이터 검증 및 manifest 생성 실행 파일
- `scripts/train.py`: Test를 사용하지 않는 E0 학습 실행 파일
- `artifacts/e0/`: 데이터 목록, 분할 결과 및 진단 정보
- `artifacts/e0/smoke/`: 소규모 실행의 체크포인트와 평가 산출물
- `docs/day1_2026-10-14.md`: Day 1 수행 내용 요약

## 최종 의견

현재 구현은 E0 전체 학습을 시작할 수 있는 상태다. 데이터 준비 과정과 소규모 End-to-End 학습은 정상 동작했고 공식 test는 잠겨 있다.

다음 단계는 새로운 기능을 추가하는 것이 아니라 공식 S3에서 동기화하고 검증한 `P1_CXR/chest_xray/chest_xray` 데이터를 이용해 전체 E0를 실행하는 것이다. AWS 인증, 공식 데이터 동기화, S3–로컬 개수·용량 대조 및 manifest 재생성은 완료되었다. 전체 E0 결과가 확보되기 전에는 Day 1의 모델 학습이 최종 완료되었다고 표현하지 않아야 한다.
